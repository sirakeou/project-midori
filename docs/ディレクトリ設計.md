# ディレクトリ設計

## 1. ディレクトリ
```
src/
├── main.tsx                    # ReactDOM エントリーポイント
│
├── app/                        # アプリケーションルート
│   ├── App.tsx                 # ルートコンポーネント（RouterProvider）
│   └── AppShell.tsx            # レイアウトシェル（ヘッダー、サイドメニュー）
│
├── routes/                     # react-router-dom のルート定義とルーター初期化
│
├── features/                   # 機能単位のモジュール群
│   └── <feature>/              # 各機能（workspace, specs, tasks, agents, settings等）
│       ├── types/              # feature固有の型定義
│       ├── hooks/              # feature固有のカスタムフック
│       ├── components/         # feature固有のUIコンポーネント
│       ├── pages/              # 画面単位のコンテナ
│       ├── utils/              # feature固有のユーティリティ
│       └── index.ts            # 外部公開API
│
├── shared/                     # アプリ全体で共有するモジュール群
│   ├── types/                  # 共通型定義
│   ├── config/                 # 環境設定
│   ├── constants/              # 定数値
│   ├── utils/                  # 純粋関数ユーティリティ
│   ├── components/             # 共通UIコンポーネント
│   │   ├── ui/                 # 基本UIパーツ（shadcn/ui）
│   │   ├── layout/             # レイアウト用コンポーネント
│   │   └── extended/           # 拡張UIコンポーネント
│   ├── hooks/                  # 共通カスタムフック
│   ├── services/               # 共通サービス層
│   └── assets/                 # バンドル対象アセット
│
├── __tests__/                  # 統合テスト
└── __fixtures__/               # テストフィクスチャ

public/                         # 静的ファイル（ビルド時にコピー）
```

## 2. 各ディレクトリの役割

### main.tsx
- ReactDOMのエントリーポイント

### app/
- アプリケーションルートコンポーネントとレイアウトシェルを配置する
- `App.tsx`: RouterProviderでルーティング機能を提供する
- `AppShell.tsx`: 全画面共通のレイアウト（ヘッダー、サイドメニュー）を提供する

### routes/
- react-router-domのルート定義とルーター初期化を一元管理する
- Tauri環境に対応したMemoryRouterを使用する
- ルート構造、プレースホルダーページ、初期エントリーの設定を担当する

### features/
- 各画面の機能を、画面ごとに分割し、ページとユースケース単位のフラグメントを集約する
- 各featureは独立性を保ち、他のfeatureへの依存を最小化する
- 内部実装は `index.ts` 経由でのみ公開し、カプセル化を維持する

### shared/
- すべての画面で利用するフラグメントを集約する

## 3. 各層の役割

featuresおよびsharedは、各層の責務ごとにフォルダを分けてプログラム等を配置する。

### components
- 画面機能を提供するコンポーネントを配置する
  - 複数のfeatureで再利用されるものは `shared/components` に配置する
    - `ui/`: 基本UIパーツ（shadcn/uiベース）
    - `layout/`: レイアウト用コンポーネント（Sidebar, Header等）
    - `extended/`: uiを組み合わせた拡張コンポーネント（ConfirmDialog等）
  - feature固有のものは `features/<feature>/components/` に配置する

### services
- バックエンドとの通信を集約する（UIレイヤーから直接 `invoke` しない）

### hooks
- カスタムフックを配置する
  - 複数のfeatureで使用するものは `shared/hooks/` に配置する
  - feature固有のものは `features/<feature>/hooks/` に配置する

### types
- 型定義を行い、ドメインモデル、インターフェースを規定する
  - アプリ全体で共有する型は `shared/types/` に配置する
  - feature固有の型は `features/<feature>/types/` に配置する

### constants
- アプリ全体の定数値を `shared/constants/` に配置する
- エラーコード、エラーメッセージ、設定値などを規定する

### utils
- 純粋関数のユーティリティを配置する（副作用を持たない、再利用可能な関数群）
  - アプリ全体で使用するものは `shared/utils/` に配置する
  - feature固有のものは `features/<feature>/utils/` に配置する

### config
- 環境変数の型定義とバリデーションを規定する

### assets
- バンドル時に最適化される静的アセット（フォント等）を配置する
