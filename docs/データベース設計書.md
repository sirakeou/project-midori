# データベース設計書

## 1. 概要

スキルリストアプリケーションのデータベース設計書です。Tauri + SQLite環境でのローカルデータベース設計を定義します。

### 1.1. 技術スタック
- **データベース**: SQLite 3
- **データベースアクセス**: tauri-plugin-sql
- **フロントエンド**: React + TypeScript
- **バックエンド**: Tauri（Rust）

### 1.2. 設計原則
- **正規化**: 第3正規形まで正規化
- **命名規則**: スネークケース（例：employee_id、skill_name）
- **制約**: 外部キー制約、チェック制約を適切に設定
- **データ型**: SQLiteのサポートする型に準拠（INTEGER, TEXT, REAL, BLOB）
- **認証**: シングルユーザー想定のため認証機能は実装しない

## 2. テーブル設計

### 2.1. users（社員マスタ）テーブル

社員の基本情報を管理するマスタテーブル

#### カラム定義
| カラム名 | データ型 | NULL | 制約 | 説明 |
|---------|---------|------|------|------|
| employee_id | TEXT | NO | PK | 社員番号（6桁数字） |
| name | TEXT | NO | | 氏名 |
| position | TEXT | NO | CHECK | 役職（enum値） |
| created_at | TEXT | NO | DEFAULT CURRENT_TIMESTAMP | 作成日時（ISO8601形式） |
| updated_at | TEXT | NO | DEFAULT CURRENT_TIMESTAMP | 更新日時（ISO8601形式） |

#### 制約
- **主キー**: employee_id
- **チェック制約**:
  - employee_id は6桁の数字のみ（`LENGTH(employee_id) = 6 AND employee_id GLOB '[0-9][0-9][0-9][0-9][0-9][0-9]'`）
  - position は定義済み値のみ（`position IN ('ANALYST', 'CONSULTANT', 'SENIOR_CONSULTANT', 'MANAGER', 'SENIOR_MANAGER','DIRECTOR', 'PARTNER')`）

#### インデックス
- **PRIMARY**: employee_id
- **INDEX**: position（検索用）

#### DDL
```sql
CREATE TABLE users (
  employee_id TEXT PRIMARY KEY CHECK(LENGTH(employee_id) = 6 AND employee_id GLOB '[0-9][0-9][0-9][0-9][0-9][0-9]'),
  name TEXT NOT NULL,
  position TEXT NOT NULL CHECK(position IN ('ANALYST', 'CONSULTANT', 'SENIOR_CONSULTANT', 'MANAGER', 'SENIOR_MANAGER','DIRECTOR', 'PARTNER')),
  created_at TEXT NOT NULL DEFAULT CURRENT_TIMESTAMP,
  updated_at TEXT NOT NULL DEFAULT CURRENT_TIMESTAMP
);

CREATE INDEX idx_users_position ON users(position);
```

### 2.2. skills（スキルマスタ）テーブル

スキル定義を管理するマスタテーブル

#### カラム定義
| カラム名 | データ型 | NULL | 制約 | 説明 |
|---------|---------|------|------|------|
| id | INTEGER | NO | PK AUTOINCREMENT | スキルID（自動採番） |
| name | TEXT | NO | UNIQUE | スキル名 |
| category1 | TEXT | NO | CHECK | スキルカテゴリ1 |
| category2 | TEXT | YES | CHECK | スキルカテゴリ2（TECHNICALのみ） |
| description | TEXT | YES | | スキル説明 |
| created_at | TEXT | NO | DEFAULT CURRENT_TIMESTAMP | 作成日時（ISO8601形式） |
| updated_at | TEXT | NO | DEFAULT CURRENT_TIMESTAMP | 更新日時（ISO8601形式） |

#### 制約
- **主キー**: id
- **一意制約**: name
- **チェック制約**:
  - category1 は定義済み値のみ（`category1 IN ('BUSINESS', 'INDUSTRY', 'TECHNICAL')`）
  - category2 は null または定義済み値のみ（`category2 IS NULL OR category2 IN ('STRATEGY', 'DATA_MANAGEMENT', 'AI')`）
  - category1 が BUSINESS または INDUSTRY の場合、category2 は null（`(category1 IN ('BUSINESS', 'INDUSTRY') AND category2 IS NULL) OR category1 = 'TECHNICAL'`）

#### インデックス
- **PRIMARY**: id
- **UNIQUE**: name
- **INDEX**: category1（検索用）
- **INDEX**: (category1, category2)（複合検索用）

#### DDL
```sql
CREATE TABLE skills (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  name TEXT NOT NULL UNIQUE,
  category1 TEXT NOT NULL CHECK(category1 IN ('BUSINESS', 'INDUSTRY', 'TECHNICAL')),
  category2 TEXT CHECK(category2 IS NULL OR category2 IN ('STRATEGY', 'DATA_MANAGEMENT', 'AI')),
  description TEXT,
  created_at TEXT NOT NULL DEFAULT CURRENT_TIMESTAMP,
  updated_at TEXT NOT NULL DEFAULT CURRENT_TIMESTAMP,
  CHECK((category1 IN ('BUSINESS', 'INDUSTRY') AND category2 IS NULL) OR category1 = 'TECHNICAL')
);

CREATE INDEX idx_skills_category1 ON skills(category1);
CREATE INDEX idx_skills_category ON skills(category1, category2);
```

### 2.3. skill_assessments（スキル保有）テーブル

社員のスキル評価を管理するファクトテーブル

#### カラム定義
| カラム名 | データ型 | NULL | 制約 | 説明 |
|---------|---------|------|------|------|
| id | INTEGER | NO | PK AUTOINCREMENT | 評価ID（自動採番） |
| employee_id | TEXT | NO | FK | 社員番号 |
| skill_id | INTEGER | NO | FK | スキルID |
| level | INTEGER | NO | CHECK | スキルレベル（0-5） |
| updated_at | TEXT | NO | | 更新日時（ISO8601形式、バージョン管理） |
| created_at | TEXT | NO | DEFAULT CURRENT_TIMESTAMP | 作成日時（ISO8601形式） |

#### 制約
- **主キー**: id
- **外部キー**:
  - employee_id → users.employee_id
  - skill_id → skills.id
- **一意制約**: (employee_id, skill_id, updated_at)（同一バージョンでのスキル重複防止）
- **チェック制約**: level は 0-5 の範囲内（`level >= 0 AND level <= 5`）

#### インデックス
- **PRIMARY**: id
- **UNIQUE**: (employee_id, skill_id, updated_at)
- **INDEX**: employee_id（社員別検索用）
- **INDEX**: skill_id（スキル別検索用）
- **INDEX**: updated_at（バージョン別検索用）
- **INDEX**: (employee_id, updated_at)（社員の特定バージョン検索用）

#### DDL
```sql
CREATE TABLE skill_assessments (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  employee_id TEXT NOT NULL,
  skill_id INTEGER NOT NULL,
  level INTEGER NOT NULL CHECK(level >= 0 AND level <= 5),
  updated_at TEXT NOT NULL,
  created_at TEXT NOT NULL DEFAULT CURRENT_TIMESTAMP,
  FOREIGN KEY (employee_id) REFERENCES users(employee_id) ON DELETE CASCADE,
  FOREIGN KEY (skill_id) REFERENCES skills(id) ON DELETE CASCADE,
  UNIQUE(employee_id, skill_id, updated_at)
);

CREATE INDEX idx_skill_assessments_employee ON skill_assessments(employee_id);
CREATE INDEX idx_skill_assessments_skill ON skill_assessments(skill_id);
CREATE INDEX idx_skill_assessments_updated ON skill_assessments(updated_at);
CREATE INDEX idx_skill_assessments_employee_updated ON skill_assessments(employee_id, updated_at);
```

### 2.4. personal_profiles（私の説明書）テーブル

社員の人物情報・働き方属性を管理するテーブル

#### カラム定義
| カラム名 | データ型 | NULL | 制約 | 説明 |
|---------|---------|------|------|------|
| id | INTEGER | NO | PK AUTOINCREMENT | プロフィールID（自動採番） |
| employee_id | TEXT | NO | FK | 社員番号 |
| photo_path | TEXT | YES | | プロフィール写真ファイルパス |
| career | TEXT | YES | CHECK | これまでのキャリア（最大2000文字） |
| hobbies | TEXT | YES | CHECK | 趣味（最大2000文字） |
| self_introduction | TEXT | YES | CHECK | 自分はこんな人（最大2000文字） |
| triggers | TEXT | YES | CHECK | 地雷はこれ（最大2000文字） |
| work_preferences | TEXT | YES | | 働き方選択（JSON文字列形式） |
| updated_at | TEXT | NO | | 更新日時（ISO8601形式、バージョン管理） |
| created_at | TEXT | NO | DEFAULT CURRENT_TIMESTAMP | 作成日時（ISO8601形式） |

#### 制約
- **主キー**: id
- **外部キー**:
  - employee_id → users.employee_id
- **一意制約**: (employee_id, updated_at)（同一社員・同一更新日時での重複防止）
- **チェック制約**:
  - career, hobbies, self_introduction, triggers は各2000文字以内
  - work_preferences は有効な JSON 文字列（アプリケーション層でバリデーション）

#### インデックス
- **PRIMARY**: id
- **UNIQUE**: (employee_id, updated_at)
- **INDEX**: employee_id（社員別検索用）
- **INDEX**: updated_at（バージョン別検索用）

#### DDL
```sql
CREATE TABLE personal_profiles (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  employee_id TEXT NOT NULL,
  photo_path TEXT,
  career TEXT CHECK(LENGTH(career) <= 2000),
  hobbies TEXT CHECK(LENGTH(hobbies) <= 2000),
  self_introduction TEXT CHECK(LENGTH(self_introduction) <= 2000),
  triggers TEXT CHECK(LENGTH(triggers) <= 2000),
  work_preferences TEXT,
  updated_at TEXT NOT NULL,
  created_at TEXT NOT NULL DEFAULT CURRENT_TIMESTAMP,
  FOREIGN KEY (employee_id) REFERENCES users(employee_id) ON DELETE CASCADE,
  UNIQUE(employee_id, updated_at)
);

CREATE INDEX idx_personal_profiles_employee ON personal_profiles(employee_id);
CREATE INDEX idx_personal_profiles_updated ON personal_profiles(updated_at);
```

## 3. ビュー設計

### 3.1. latest_skill_assessments（最新スキル評価）ビュー

各社員の最新スキル評価を効率的に取得するためのビュー

```sql
CREATE VIEW latest_skill_assessments AS
SELECT
    sa.id,
    sa.employee_id,
    sa.skill_id,
    sa.level,
    sa.updated_at,
    s.name as skill_name,
    s.category1,
    s.category2
FROM skill_assessments sa
INNER JOIN skills s ON sa.skill_id = s.id
WHERE sa.updated_at = (
    SELECT MAX(updated_at)
    FROM skill_assessments
    WHERE employee_id = sa.employee_id
    AND skill_id = sa.skill_id
);
```

### 3.2. employee_skill_summary（社員スキル一覧）ビュー

全社員スキル一覧表示用ビュー

```sql
CREATE VIEW employee_skill_summary AS
SELECT
    u.employee_id,
    u.name as employee_name,
    u.position,
    lsa.skill_name,
    lsa.category1,
    lsa.category2,
    lsa.level,
    lsa.updated_at
FROM users u
LEFT JOIN latest_skill_assessments lsa ON u.employee_id = lsa.employee_id
ORDER BY u.employee_id, lsa.category1, lsa.skill_name;
```

## 4. データアクセスパターン

### 4.1. tauri-plugin-sqlの使用方法

#### 基本的なクエリ実行（TypeScript/React側）

```typescript
import Database from "tauri-plugin-sql-api";

// データベース接続
const db = await Database.load("sqlite:app.db");

// SELECT クエリ
const users = await db.select<User[]>("SELECT * FROM users WHERE position = ?", [position]);

// INSERT クエリ
await db.execute(
  "INSERT INTO users (employee_id, name, position) VALUES (?, ?, ?)",
  [employeeId, name, position]
);

// UPDATE クエリ
await db.execute(
  "UPDATE users SET name = ?, updated_at = CURRENT_TIMESTAMP WHERE employee_id = ?",
  [name, employeeId]
);

// DELETE クエリ
await db.execute("DELETE FROM users WHERE employee_id = ?", [employeeId]);

// トランザクション
await db.execute("BEGIN TRANSACTION");
try {
  await db.execute("INSERT INTO ...", [...]);
  await db.execute("UPDATE ...", [...]);
  await db.execute("COMMIT");
} catch (error) {
  await db.execute("ROLLBACK");
  throw error;
}
```

### 4.2. セキュリティ考慮事項

- **SQLインジェクション対策**: 必ずプレースホルダー（`?`）を使用してパラメータをバインドする
- **バリデーション**: アプリケーション層で入力値を検証する
- **ファイルパーミッション**: データベースファイルへのアクセス権限をOS層で適切に設定
- **バックアップ**: 定期的なバックアップ機能の実装を推奨

### 4.3. 外部キー制約の有効化

SQLiteではデフォルトで外部キー制約が無効化されているため、接続時に有効化する必要があります。

```typescript
// アプリケーション起動時に実行
const db = await Database.load("sqlite:app.db");
await db.execute("PRAGMA foreign_keys = ON");
```

### 5.3. TypeScript型定義

// src/types/database.ts

export enum Position {
  ANALYST = 'ANALYST',
  CONSULTANT = 'CONSULTANT',
  SENIOR_CONSULTANT = 'SENIOR_CONSULTANT',
  MANAGER = 'MANAGER',
  SENIOR_MANAGER = 'SENIOR_MANAGER',
  DIRECTOR = 'DIRECTOR',
  PARTNER = 'PARTNER',
}

export enum SkillCategory1 {
  BUSINESS = 'BUSINESS',
  INDUSTRY = 'INDUSTRY',
  TECHNICAL = 'TECHNICAL',
}

export enum SkillCategory2 {
  STRATEGY = 'STRATEGY',
  DATA_MANAGEMENT = 'DATA_MANAGEMENT',
  AI = 'AI',

export interface User {

  name: string;
  position: Position;
  created_at: string;

export interface SkillAssessment {

  employee_id: string;

  updated_at: string;
  created_at: string;

export interface WorkPreferences {
